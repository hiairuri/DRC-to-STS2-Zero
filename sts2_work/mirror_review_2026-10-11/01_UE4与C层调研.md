## ① 结论摘要

### 1.1 一句话：手游真机观感应如何合成

```
out_sRGB = LinearToSrgb(  max(0,  1 − SrgbToLinear(albedo_sRGB) )        ← 自发光项（反相，t 恒 0）
                        + spec_direct(方向光 GGX 高光)                    ← 高亮
                        + env_indirect(反射立方图) × EnvBRDF(0.5,NoV) )   ← 环境光 + 边缘 Fresnel 增亮
           再 × FogFactor + FogInscatter                                  ← 雾（战场通常中性）
```

即：**「线性空间取反 + 线性空间加高光/环境 + sRGB 编码输出」**。
真机之所以是「白色但非纯白、带高亮光影」：

1. **非纯白**：`1 − SrgbToLinear(a)` —— 只要贴图不是纯黑，结果就 <1（实测不透明区反相后 sRGB 均值 0.71~0.77、p90 0.976，见 02 报告 §2.7/③），且**保留反相后的残余色偏** → 不是纯白。
2. **带高亮光影**：材质 **BaseColor（DiffuseColor）= 常量 0**（u066941:124 / u044281:128 双证）→ **完全没有漫反射**，观感 100% 由「自发光 + 高光 + 环境反射」构成；`EnvBRDF(Roughness=0.5, NoV)` 从正视角 **0.0296** 涨到掠射角 **0.1538**（**5.2×**）→ **边缘明显提亮**，这就是"光影"。

### 1.2 与现移植的差距（三处，按影响排序）

| # | 现移植 | 真值 | 影响 |
|---|---|---|---|
| **D1（主因嫌疑）** | `1 − base.rgb` **在 sRGB 空间直接取反** | **线性空间取反 + sRGB 编码**（运行时捕获实锤，见 §2.4） | 同一份贴图：sRGB 直取反 ≈ **0.35**，线性取反再编码 ≈ **0.75**，**差约 2 倍** → 这就是用户说的"太暗/发黑"。**反相本身不是 bug，取反所在的色彩空间才是** |
| **D2** | `spec + env → sheen = 0`（当作 2D 中性） | DiffuseColor=0 ⇒ **高光与环境反射是唯一"光影"来源**，量级 0.03~0.92（线性） | 丢掉"高亮光影"的来源 |
| **D3** | 语义错但数值巧合 | `TEXCOORD7` **不是体积透射光/环境加色，是雾**（VS u024490 实锤） | 中性值恰好同为 (w=1, xyz=0)，**但不能靠调 `light_w`/`ambient_add` 来补亮度**——雾不产生亮度 |

### 1.3 反相项 t："恒为 0"被重新钉死（且不再依赖 C 层假设）

`t = clamp( (MaxDarkenAlpha / (FarDistance − NearDistance)) × max(depth − NearDistance, 0), 0, capMul × MaxDarkenAlpha )`

- **DarkenMPC 资产默认：`NearDistance=50.0`、`FarDistance=1024.0`、`MaxDarkenAlpha=0.0`**（`unpacked/res_parentmaterials/mpc/darkenmpc.uexp` 属性转储，见 §2.3）
- ⇒ `slope = 0 / 974 = 0`，`cap = capMul × 0 = 0` ⇒ **t 恒为 0，与 `darkenParam` 取 0 还是 1 完全无关**。
- ⇒ 历史定案里"材质默认 1.0 会扫除反相"的说法 **作废**；"组件 +0x920 无人写 = 0" 这条**无法复核的 C 层假设不再必要**（结论不变，但因果链换成了可复核的资产事实）。

### 2.4 Shader（19 份提取 GLSL 逐行重解码）

配对关系：`u024490_VS.glsl` 与 `u066941_FS.glsl` 的 varying 集**逐项一致**
（`TEXCOORD10/TEXCOORD11/COLOR0/TEXCOORD0/TEXCOORD5/TEXCOORD7/TEXCOORD8`，location 0..6）⇒ 同一 program。
同族互证：`u044281_FS.glsl`（无 SH/ILC 的简化变体）、`u071049_FS.glsl`（u066941 的兄弟变体）逐项对得上。

#### (a) 顶点侧关键语义（u024490_VS.glsl）

| varying | 计算 | 语义 |
|---|---|---|
| `var_COLOR0` | `v82 = in_ATTRIBUTE3.zyxw` | **spine slot 顶点色**（BGRA→RGBA 重排），`ATTRIBUTE3=mediump vec4` |
| `var_TEXCOORD0` | `t79[0].xy = ATTRIBUTE4` | UV（采样用） |
| `var_TEXCOORD8` | `v11.xyz = (LocalToWorld × ATTRIBUTE0) + PreViewTranslation`，`.w = clipW` | **TranslatedWorldPosition**（相机相对世界坐标） |
| `var_TEXCOORD7` | `v10 = v60/v63`（高度雾 + 体积雾） | **★ 雾**：`w = FogFactor`，`xyz = FogColor×(1−FogFactor) + 日照散射` |
| `var_TEXCOORD5` | `v85.x = clamp((len·vu.z − vu.x)/(vu.y − vu.x),0,1)` | 深度/雾相关标量 |

TEXCOORD7 推导链（u024490）：

**无雾 / 雾末端之外：w=1、xyz=0 ⇒ 恒等。**

## ③ 与历史定案的冲突与作废项

| # | 历史定案（条目 26） | 本轮裁定 | 理由与证据 |
|---|---|---|---|
| **V1** | 「C 写 `darkenParam = 组件+0x920 = 0` ⇒ cap=0 ⇒ t=0 ⇒ 全程反相」 | **结论保留，因果链修正** | 真因 = **DarkenMPC.MaxDarkenAlpha 资产默认 0.0**（`darkenmpc.uexp` 转储）⇒ slope=0 且 cap=0 ⇒ **t 恒 0，与 darkenParam 无关**。C 层 `+0x920` 假设不再必要（且 part_*.c 已删、无法复核） |
| **V2** | 「材质默认 1.0 的『反相扫除』只在 C 主动改字段时出现」 | **作废** | `MaxDarkenAlpha=0` 时 `darkenParam=1.0` 也**不会**扫除反相（cap = 1.0×0 = 0）。**MI 无任何参数覆盖**（转储实证），故即使 C 写 1.0 也不改变观感 |
| **V3** | 「TEXCOORD7.w = 体积透射光乘子；TEXCOORD7.xyz = 环境加色」 | **语义作废（数值中性值仍成立）** | TEXCOORD7 = **雾**（`u024490_VS.glsl`：`var_TEXCOORD7 = v10 = 高度雾+体积雾结果`）。无雾时 w=1/xyz=0，与旧假设数值巧合；**但不能用作"补亮度"的旋钮** |

## ⑤ 给方案设计师的可执行结论

### 5.1 目标公式（Godot `canvas_item` 可直接实现）

```glsl
// —— 输入：base = texture(TEXTURE, UV)，v_col = 顶点色 ——
vec3 L   = srgb_to_linear(base.rgb);      // ① 图集是 sRGB 编码图像，必须先解码（若引擎已解码则跳过）
vec3 E   = max(1.0 - L, 0.0);             // ② 自发光/反相项（t 恒 0，实锤）
vec3 SH  = vec3(sheen_linear);            // ③ spec_direct + env_indirect 的平面合成（线性！不是 sRGB）
vec3 lin = E + SH;                         //    ②+③（若 sheen 想模拟"边缘高光"，按 Fresnel(NoV) 加权）
vec3 out = linear_to_srgb(lin);            // ④ 输出编码（sRGB OETF：12.92 段 / 1.055·x^(1/2.4)−0.055）
float a  = clamp(base.a * v_col.a, 0.0, 1.0);
COLOR = vec4(out, a);
```

**顺序不可颠倒**：先解码 → 线性空间取反并加高光 → 再编码。当前移植缺 ① 和 ④（即在 sRGB 空间直接取反）。

### 5.3 量级参考（用 02 报告的实测基线：不透明区 sRGB 均值 (0.652,0.629,0.608)）

| 做法 | 结果（sRGB 域） | 对应观感 |
|---|---|---|
| **sRGB 空间直接取反**（现移植，若引擎不解码） | ≈ **(0.35, 0.37, 0.39)** | **灰暗负片 ← 用户报的"太暗/发黑"** |
| **线性取反 + sRGB 编码**（真值，02 报告已算） | ≈ **(0.705, 0.757, 0.773)**，p10≈0.43~0.50，p90≈0.98 | **偏白、非纯白、带亮尾 ← 用户报的真机观感** |
| 上式再叠加线性 sheen 0.10 | ≈ +0.06~0.10（sRGB 域），暗部提升更明显 | "高亮光影"更足 |

⇒ **设计师最短路径**：先确认/修正 **① 解码 + ④ 编码**（这一个是 2 倍亮度差的主因），再谈 `sheen`。
⇒ **禁止**：为了"变白"去调 `light_w` / `ambient_add` —— 它们在源端是**雾**项，中性值就是 (1, 0,0,0)，调它们等于凭空发明参数（违反铁律 1）。
